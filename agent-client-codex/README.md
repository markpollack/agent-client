# Codex one-shot and retained lifecycle

`agent-client-codex` adapts `codex exec` to `AgentClient`'s asynchronous lifecycle. A one-shot execution runs one fresh process. A retained session (`client.sessions().create(...)`) keeps the exact thread identity emitted by the first turn's `thread.started` and runs each later turn as a replacement process on the pinned CLI's documented `codex exec resume <thread_id> ... -- -` route, with the new goal on stdin; no earlier prompt is replayed and no flag is invented. It preserves the legacy `CodexAgentModel` and SDK entry points. The current capture contract targets Codex CLI 0.166.0; deterministic subprocess tests establish the adapter behavior, not live provider qualification. Native honouring of the global sandbox/approval/`-C` flags on resume, whether `thread.started` is re-emitted on resume, and whether turn-2 `turn.completed.usage` is per-turn or cumulative remain UNVERIFIED until a bounded native smoke.

```java
var provider = CodexClientProvider.builder()
    .codexPath("/absolute/path/to/codex")
    .workingDirectory(workspace)
    .acquisitionDirectory(captures, "0.166.0")
    .build();
try (var client = AgentClient.builder(provider)
        .defaultWorkingDirectory(workspace)
        .defaultTimeout(Duration.ofMinutes(3))
        .build()) {
    var execution = client.goal("Describe this workspace").runAsync();
    var response = execution.result();
    var termination = execution.awaitTermination(Duration.ofSeconds(5));
}
```

The child receives the effective request working directory, explicit sandbox and noninteractive approval flags, `--no-daemon`, `exec --ignore-user-config --json`, and the exact UTF-8 goal through stdin (`-- -`). The default sandbox is read-only. `sandbox(...)` explicitly selects another native sandbox; `skipGitCheck(true)` is optional. Existing local authentication is used. The adapter neither copies credentials nor changes shared configuration. User rules remain enabled. Model, effort, environment and timeout come from `AgentOptions`.

Cancellation targets the one owned invocation with either interruption flag, even after a successor turn starts. Client deadline arbitration and bounded observed-process/reader cleanup are separate from the provider's reported result. Cleanup tracks the direct process and observed descendants; it does not certify process-group containment or rule out escaped children. Provider rule for retained history: any turn that does not end with a parsed successful `turn.completed` (cancellation, deadline, transport failure, `turn.failed`, identity mismatch, truncated stdout) quarantines the thread; the next `prepare` fails with `SETUP_FAILED` and closing the session is the only exit. A cancelled process does not by itself prove the native history is safe to resume. There is no replay, cross-handle history loading or native progress capability; response metadata carries `turnIndex`, `identitySource` (`stdout` or `resume-argv`) and `resumedThread`. Unsupported portable max-turn, schema, system-instruction, MCP, extra-option and interactive approval requests fail explicitly before launch. No hard dollar cap or internal model-turn bound is claimed. Reported token usage is retained as source observations; no price or missing quantity is inferred.

To archive a one-shot turn, configure `JournalExecutionRecorder` from `agent-client-journal`: the turn seals a typed `NativeGeneration` and the recorder qualifies it under `client-terminal-codex-0.166.0/1`. A custom recorder that does not take generations can still override `prepare(decision, evidence)`. `evidence.get("codexAcquisition")` supplies a `CodexAcquisition`; `writeManifest(decision)` freezes the exact owning decision/session attribution. This optional recording lane runs after result acceptance. A plain decision function does not request source materialization. Keep the original decision and manifest bytes for Journal's independent qualifier and final archive attachment. Acquisition completeness is distinct from Journal acceptance. Once the recording lane has sealed the generation, `execution.recording().evidence().fullRecord()` names the sealed manifest (URI, acquisition profile, SHA-256), also when the execution failed or the recorder did not attach the sources; the manifest carries argv, exit status, observed processes and the stdin/stdout/stderr sources. It is diagnostic evidence, not Journal qualification, and it is absent if the client closes before the lane runs, so wait for termination and a terminal recording delivery before closing.

For a retained session each turn seals its own process originals; the native rollout is re-selected by exact `-<thread_id>.jsonl` suffix and the earlier turn's sealed bytes must be an unchanged prefix (`native_prefix_before`/`native_prefix_after`, `native_records`, `cumulative_usage` and `wire_usage` in the manifest template). A forked thread or a changed prefix leaves the acquisition incomplete. Original stdin, stdout and stderr are captured independently before decode or redaction, with a 4 MiB retained limit per stream. Overflow remains explicit; truncated stdout cannot produce a successful response. Native rollout acquisition is bounded to 16 MiB and a 20,000-entry inventory. It selects only a new exact-thread filename whose session metadata matches the observed stdout identity, cwd, CLI version and exec route. Preexisting, ambiguous, missing, symlinked or mismatched sources remain incomplete. There is no latest-file fallback. Use `nativeSessionsDirectory(...)` when the native session root differs. Natural EOF and observed byte totals remain distinct from forced closure. Source files may contain sensitive task data; choose an application-owned private capture directory.
